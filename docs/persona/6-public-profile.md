# Persona 6. The public profile

Goal: LinkedIn and every other public page say the same thing as the resume. Recruiters and background
checks compare them.

## Quiet search first

Read `../08-outreach.md`, "Quiet search while employed". Before any edit, have the user turn off the setting
that tells their network about profile changes (search LinkedIn's settings for "profile updates"). No "Open
to work" banner unless they choose it. The recruiters-only version is not a guarantee: recruiters at related
companies, or at agencies the employer uses, may still see it. A full rewrite in one evening gets noticed:
offer to spread the edits over a week or two.

## Who edits

You draft every field under "Profile text" in `<data>/PERSONA.md`. The user pastes each field in, or
approves it before you type it in their browser (AGENTS.md rule 7: one yes per item). They sign in.

## LinkedIn, field by field

Character limits change. Trust the counter under the box.

- **Headline** (about 220 characters): the LinkedIn title layer (Rule 3) plus two or three strengths in
  words a recruiter searches. Never "seeking opportunities".
- **About** (about 2,600 characters. The first three lines show before "see more"): first person, in their
  voice. The one-liner. What they do day to day and at what scale. Two or three proof points. A tools line.
  What they want next only if the search is public.
- **Experience.** Title per the title layer. Employer and months exactly as PROFILE.md. Two to four lines of
  scope and capability per job.
- **Public numbers.** A figure that is fine on a resume sent privately may not be fine in public, where the
  employer reads it. For each figure ask: "OK to publish this?" Default to scope without the figure.
- **Education and certifications.** Exact names, with the issuer's credential ID or link where there is
  one. An unfinished degree gets no end year unless the user gives an expected one.
- **Skills.** From SKILLS.md, "daily at work" and "project at work" only. Put the ones the target postings
  ask for at the top. Remove any they can't back.
- **Featured, projects, publications.** Public work only.
- **Recommendations.** The user asks for them. You draft the request. None are ever written for someone to
  sign.
- **Photo, banner, custom URL.** Their choice. Suggest a plain custom URL.

## Other pages

- Code hosting: a profile README with the one-liner, and pinned projects whose READMEs say what it is, why
  it exists and how to run it. Check for passwords and keys first. An employer's code is never public.
- A portfolio site, an email signature, speaker or author bios (PERSONA.md), the links in the resume's
  contact line.
- Job-board profiles: the same facts. On a quiet search, set the resume there to private.

## The consistency check

One table in PERSONA.md: each fact (job titles, employer names, start and end months, degree status,
certification names, numbers) against the resume, LinkedIn, the application forms and any other page. A
mismatch that isn't a recorded title layer is fixed, or decided in `<data>/DECISIONS.md`. Run it after every
change to the resume or the profile.

## Search for them

With the user, search their name as a recruiter would. Look for stale job-board resumes, old profiles and
public posts. The user decides what to clean up.

## Posts

Draft on request only. Nothing is posted without the user approving the exact text. On a quiet search, no
job-hunt signals.

## Done when

PERSONA.md "Profile text" holds every field, the user approved each, the consistency check is clean, and
PROGRESS.md says `persona: profile text approved YYYY-MM-DD`.
